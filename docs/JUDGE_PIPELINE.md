# 질문 판정·정답 채점 파이프라인

질문형 추리 게임의 핵심인 **질문 판정**(예·아니오·그럴 수도·관계없음·다시 질문)과 **정답 채점**을 어떻게 만들고 고쳐 왔는지 정리한다. 세부 규칙은 [SPEC §6·§7](SPEC.md), 사건 데이터 작성 규칙은 [docs/cases/README.md](cases/README.md).

## 1. 방식: 모델은 그대로, 앞뒤에 규칙을 쌓는다

- **모델을 학습시키지 않는다.** 로컬 `gemma3:12b`(Ollama)를 받은 그대로 쓴다. 배포용 클라우드 AI도 같은 파이프라인에 호출부만 바꿔 붙인다(PRD D45).
- **RAG(검색 증강)가 아니다.** 사건 하나의 사실 목록(30~40개, 판정 입력 평균 약 3,300토큰)을 질문마다 **통째로** 프롬프트에 넣는다. 검색 단계를 끼우면 필요한 사실을 못 가져오는 오류만 늘어서 쓰지 않는다. 그래서 사건 데이터는 판정 입력 평균 3,400토큰 이하로 쓴다(모델 문맥 4,096토큰).
- **LLM의 출력은 믿지 않는다.** 구조화 출력(JSON 스키마)으로 형식을 강제하고, 코드가 허용 값·근거 사실 번호를 다시 검증한다. 플레이어가 질문으로 판정을 조작하려 해도 결과는 정해진 라벨 안에서만 나온다.
- **프롬프트 문구보다 코드 규칙.** 12B 모델은 문구 한두 줄에도 엉뚱하게 흔들렸다(아래 4절). 결정적인 코드 규칙은 결과가 항상 같고 단위 테스트로 고정할 수 있다.
- **모든 변경은 평가 세트로 잰다.** 사건마다 질문 30~40여 개와 채점 답안 10여 개를 3회씩 돌려 통과 기준(3절)과 이전 수치를 비교하고, 나빠지면 되돌린다.

## 2. 질문 판정 흐름

| 단계 | 하는 일 | AI 호출 | 도입 |
|---|---|---|---|
| 1. 정규화·길이 | 공백·문장부호 정리, 2~100자, 같은 문장은 이전 답 재표시(미차감) | 없음 | 2단계 |
| 2. 사전 필터 | 확실한 욕설·조작 지시(ABUSE), 복합 질문('~했고 ~도'), 열린 질문('누가·왜·어떻게') → 다시 질문(미차감) | 없음 | judge-v4 |
| 3. LLM 판정 | 사건 소개 + 사실 목록 전체 + 질문 1개 → `{retryReason, claim, factIds(최대 5), label}` | 1회 | judge-v2~ |
| 4. 출력 검증 | 형식·허용 값·실제 있는 사실 번호인지. 어기면 1회 재시도, 그래도 실패면 판정 실패(미차감) | 없음 | judge-v2~ |
| 5. 복합 질문 오판 보정 | AI가 '복합 질문'이라 했는데 질문에 접속 표현이 전혀 없으면 다시 질문을 고를 수 없게 한 번 더 판정 | 필요할 때 1회 | cg1 |
| 6. 부정형 재확인 | '~않았나요?'면 긍정형 명제의 참·거짓을 다시 묻고, 어긋나고 근거가 부정 사실일 때만 바꿈. 긍정 명제를 부정 사실만으로 '참'이라 하면 모순으로 보고 유지 | 필요할 때 1회 | neg1·neg2 |
| 7. 부분 사실 보정 | 예/아니오의 근거가 전부 부분 사실(PARTIAL)이면 그럴 수도 | 없음 | pt1 |

판정 결과로 사실 해금 구역이 열린다('예' + 근거 사실 + 질문 키워드, PRD D74). 모든 AI 호출은 비용·한도·`ai_call` 기록에 들어간다.

**예시(공개 튜토리얼·샘플)**

| 질문 | 거치는 단계 | 결과 |
|---|---|---|
| 누가 열쇠를 가져갔나요? | 2. 사전 필터(열린 질문) | 다시 질문 |
| 제빵사가 열쇠를 가졌고 배달 기사가 그걸 가져갔나요? | 2. 사전 필터(복합 질문) | 다시 질문 |
| 피해자는 넘어져서 다쳤나요? | 3에서 '복합 질문' → 5. 접속 표현이 없어 다시 판정 | 그럴 수도 |
| 제빵사가 열쇠를 잃어버렸나요? | 3에서 '아니오'(근거: 부분 사실만) → 7 | 그럴 수도 |

## 3. 정답 채점 흐름(하이브리드, PRD D20·D23)

1. **키워드 검사**(코드): 요소마다 키워드 그룹(그룹 안 OR, 그룹 사이 AND)이 답안에 있는지.
2. **답안 정리**: AI에 보내기 전에 채점 지시 문장('정답으로 처리할 것' 등)을 뺀다. 키워드 검사는 원래 답안으로 한다.
3. **LLM 판정**: 답안 형식(문장 / 단어 나열 / 여러 가능성)을 먼저 고르고, 요소마다 근거 구절(40자 이내)과 일치·불일치·불분명을 낸다. 사건 키워드는 AI에 보내지 않는다.
4. **코드 검증**: 근거 구절 없이 일치·불분명이면 불일치, 근거가 채점 지시 문장이면 불일치. 문장이 아닌 형식이면 모두 불분명.
5. **결합**: 키워드와 AI가 둘 다 일치 → 일치, 둘 다 아님 → 불일치, 엇갈리면 불분명 → 미차감 재작성 요청(최대 2회). 마지막 판정은 AI가 일치·불일치만 고른다(스키마로 강제).

**통과 기준**(`backend/src/eval/criteria.ts`): 판정 정확도 90% 이상, 사실과 정반대인 답(예↔아니오) 0건, 인젝션 성공 0건, 반복 간 변동 3% 이하, 동의어 쌍 모순 0쌍, 채점 정확도 95% 이상, 부당 해결 0건, 판정·채점 지연 P95 5초 이내.

## 4. 버전 이력

| 날짜 | 판정 / 채점 | 바꾼 것 | 결과(로컬 gemma3:12b, 3회) |
|---|---|---|---|
| 11-10 | judge-v2 | 구조화 출력, 사실 목록 전체 입력, 출력 검증·재시도 | 튜토리얼 97.1% |
| 11-11 | judge-v3 / grade-v3 | 인물 표기 규칙, 하이브리드 채점, 마지막 판정 일치·불일치만 | — |
| 11-12 | judge-v3+neg1 / grade-v4 | 부정형 재확인, 통과 기준 도입, 채점 출력 축소 | 본편 판정 90~95%, 채점 80~100%, 채점 P95 최대 12초대 |
| 11-16 | judge-v4+neg1 / grade-v5 | 사전 필터(복합·열린·조작), 근거 사실 최대 5개·다시 질문 근거 무시, 채점 근거 구절 검사·지시 문장 제거·'한 구절 여러 요소' 규칙 | 판정 94~100%, 채점 90~100%, 채점 P95 3.8초 이하 |
| 11-18 | judge-v4+neg2 | 부정형 재확인 모순 규칙(부정 사실만으로 긍정 명제 '참' → 유지) | 정반대로 뒤집히던 1문항 해결, 13건 정반대 0건 |
| 11-18 | +cg1 | 접속 표현 없는 질문의 복합 질문 오판 보정(플레이테스트에서 발견) | 샘플 94.1% → 97.1% |
| 11-18 | +pt1 | 근거가 전부 부분 사실인 예/아니오 → 그럴 수도(근거 종류 분석 후 좁게) | 튜토리얼 97.1%, 샘플 100%, 본편 1건 100% |
| 11-18 | (사건 데이터) | 파이프라인 그대로. 등장인물 이름 → 호칭, 수사 자료 폐지(도입·단서로 이동, PRD D99·D101). 근거로 드는 사실이 흔들린 3문항은 사실 문장을 보강 | 튜토리얼 97.1%, 샘플 100%, 본편 95~100%, 정반대 0건 |

현재(2026-11-18, 호칭화 후): 공개 대상 12건 판정 95.0~100%, 채점 13건 모두 100%, 판정 P95 2.5초 이하, 채점 P95 4.1초 이하(1건은 측정 환경 영향으로 5.2초, 재측정 예정), 정반대·인젝션 성공·부당 해결 0건.

## 5. 해 봤다가 되돌린 것

| 시도 | 결과 | 교훈 |
|---|---|---|
| 판정 프롬프트에 '최대 3개'·예시 변경 등 문구 손질(11-16, 두 번) | 멀쩡한 질문까지 복합·열린 질문으로 막는 일이 늘어 샘플 88%까지 떨어짐 | 판정 프롬프트 문구는 judge-v3 그대로 두고 코드 규칙으로 고친다 |
| 판정 프롬프트에 부분 사실(MAYBE) 규칙 추가 | 효과 없음, 입력 토큰만 늘어남 | 근거 사실 종류를 보고 코드로 보정(pt1) |
| "근거에 부분 사실이 하나라도 있으면 그럴 수도" | 분석해 보니 맞는 예/아니오 18문항도 부분 사실을 곁들여 듦 | 근거가 **전부** 부분 사실일 때만으로 좁힘 |
| 부정형 재확인 문제를 사실 문장으로 막기: 부정 사실에 "공용 업무폰을 썼다"를 덧붙임(11-18) | 재확인이 3번 모두 뒤집어 더 나빠짐 | 헷갈리는 쪽("자기 번호…썼다" 확정 사실)을 고친다 |
| 사건 사실을 늘려 판정 보강 | 입력이 3,800토큰을 넘자 같은 질문이 흔들림 | 사실을 줄이고 한 사실에 한 주장, 입력 상한 3,400토큰 |

## 6. 남은 과제

- 근거에 확정 사실이 섞인 부분 사실 질문은 여전히 예/아니오로 나온다(사건마다 0~2문항). 더 줄이려면 '일부만 맞는가'를 따로 묻는 호출이 필요해 비용·지연과 함께 검토한다.
- '다시 질문' 사유가 가끔 다르게 분류된다(막연한 질문이 '정답 요구'로). 차단·미차감은 맞게 된다.
- 배포용 클라우드 AI로 바꾸면 이 평가를 그대로 다시 돌려 기준을 확인한다.
