# 사건 작성 규칙

사건 하나를 만들고 공개하기까지의 규칙이다(PRD D65, SPEC §11). 사건은 `case.json`(맵 포함)과 `eval.json` 두 파일로 이루어진다. 공개 저장소에는 튜토리얼·샘플만 두고, 출시용 본편은 비공개 폴더(`CASE_DATA_DIR`)에 둔다(D85).

## 1. 제작 순서
1. **사건 문서**: 진상(누가·어떻게·왜), 인물, 타임라인, 핵심 증거를 먼저 정한다. 발상만 빌리고 완전히 창작하며, 실명·실제 장소·실제 피해자를 특정하지 않는다(D34).
2. **개연성 점검**: 아래 §2 점검표를 모두 통과시킨다.
3. **데이터 작성**: `case.json`의 사실 목록·정답 요소·힌트·맵·단서를 쓴다. 적재 전 자동 검사(`npm test`)를 통과해야 한다.
4. **평가 세트**: 질문 30개 이상·채점 답안 8개 이상을 쓰고 AI로 측정한다(§5).
5. **플레이테스트**: 처음 보는 사람이 끝까지 풀어 보고, 막힌 지점과 억지스러운 부분을 기록한다.
6. **최종 승인**: 사용자가 승인한 뒤 공개한다. 내용을 바꾸면 `version`을 올린다(같은 버전으로 내용만 바꾸면 적재가 거부된다).

## 2. 개연성 점검표
- 진상만으로 공개된 모든 단서·증언·타임라인이 설명되는가(설명되지 않는 단서가 없는가)?
- 범인(또는 원인)의 행동에 그럴 만한 동기와 기회가 있는가?
- 진상에 도달하는 데 필요한 사실을 질문으로 모두 확인할 수 있는가(사실 목록에 빠진 고리가 없는가)?
- 미끼 단서는 진상과 모순되지 않고, 엔딩에서 왜 미끼였는지 설명되는가?
- 단서·NPC 대사가 진상을 직접 말하지 않는가(D28)?
- 표현 수위가 사건 등급(보통·강함)과 공통 금지 사항을 지키는가(D35)?

## 3. 사실 목록 쓰는 법
AI 판정은 사실 목록만 근거로 한다. 질문으로 확인할 수 있어야 하는 내용은 모두 사실로 적는다.

- **한 사실에는 한 가지 내용만** 쓴다. 여러 내용을 한 문장에 몰면 판정이 흔들린다.
- **종류를 정확히 고른다.**
  - `FACT`: 확정 사실.
  - `NEGATIVE`: "~가 아니다/없다/않았다". 플레이어가 자주 의심할 오답 방향(외부인, 도난, 독살 등)은 반드시 부정 사실로 막아 둔다.
  - `PARTIAL`: 일부만 맞거나 조건에 따라 달라지는 사실. '그럴 수도' 판정의 유일한 근거다(D2).
- **부분 사실은 "무엇이 맞고 무엇이 틀린지"를 한 문장에 함께 쓴다.** 예: "오태준은 열쇠가 든 자루를 옮겼으므로 열쇠를 가져간 셈이지만, 열쇠가 있는 줄 몰랐고 가져갈 의도도 없었다." 맞는 쪽만 쓰면 AI가 '예'로, 틀린 쪽만 쓰면 '아니오'로 답한다.
- 부분 사실은 **플레이어가 실제로 물을 법한 표현**(가져갔나요, 잃어버렸나요, 인정했나요)이 문장 안에 들어가게 쓴다.
- 사실 사이에 모순이 없어야 한다. 시간이 바뀌는 사실은 시점을 적는다("그날 밤", "다음 날 아침").

## 4. 인물 표기(자동 검사)
- 관련자마다 겹치지 않는 지칭을 붙인다. 지칭은 역할 표기의 괄호 앞부분이다(예: '사장(의뢰인)' → 사장).
- 사실·정답 요소·힌트에서는 이름을 항상 '지칭 이름'으로 쓴다(예: "조카 문태성"). 도입 이야기·해설은 자유롭게 쓴다.
- 정답 키워드에 성명을 넣으면 이름만(성 제외)과 지칭도 함께 넣는다(예: 조카 / 문태성 / 태성).

## 5. 평가 세트와 통과 기준
- 질문 30개 이상: 직접 질문, 부분 사실, 동의어 쌍(`pairId`), 부정형, 복합·열린 질문, 정답 직접 요구, 인젝션, 정의되지 않은 세부, 욕설, 모호한 질문을 고루 넣는다.
- 채점 답안 8개 이상: 완전한 정답, 동의어·다른 호칭, 선택 요소 없는 정답, 오답(범인·방법 틀림), 부분 정답, 단어 나열, 여러 가능성 나열, 인젝션. 마지막 판정 기대값(`expectedFinal`)도 쓴다.
- 측정: `npm run eval -w backend -- --case <사건> --repeat 3`, `npm run eval:grade -w backend -- --case <사건> --repeat 3`(마지막 판정은 `--final`).
- **통과 기준**(판정 안정성 작업에서 정함, `backend/src/eval/criteria.ts`):

| 구분 | 기준 |
|---|---|
| 판정 정확도 | 90% 이상 |
| 사실과 정반대인 답(예↔아니오) | 0건 |
| 인젝션 성공 | 0건 |
| 반복 간 변동 | 3% 이하 |
| 동의어 쌍 모순 | 0쌍 |
| 채점 정확도 | 95% 이상 |
| 부당 해결(해결되면 안 되는 답안이 해결) | 0건 |
| 판정·채점 지연 P95 | 5초 이내 |

- 미달이면 먼저 사실 목록을 고친다(빠진 사실, 한 문장에 몰린 내용, 부분 사실 쓰는 법). 프롬프트는 여러 사건에 공통이므로 사건 하나에 맞춰 바꾸지 않는다.

## 6. 맵·단서
- 맵은 글자 격자('#' 벽, '.' 바닥). 첫 맵은 처음부터 열고, 탐정이 실제로 지나왔을 길(현관 등)을 잠그지 않는다.
- 구역 해금은 단서 해금과 사실 해금을 섞는다(D26). 사실 해금 구역에는 반드시 연결된 힌트를 둔다.
- 단서마다 그 내용을 설명하는 사실이 사실 목록에 있어야 한다(플레이어가 단서를 보고 질문하면 판정할 수 있어야 함).
- 고정 대사 NPC는 사건당 0~2명, 대사 1~3줄(D28).
