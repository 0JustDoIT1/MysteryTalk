# 사건 콘텐츠 작성 규칙 (v1.2 살인 사건)

사건 하나는 `docs/cases/<slug>.md`(수사 파일·기획 문서)와 `docs/cases/<slug>.eval.json`(평가 데이터)으로 구성한다. 시드 JSON과 Tiled 맵은 이 문서를 기준으로 만든다.
난이도별 수치는 [PRD §2](../PRD.md#2-사건-구성-및-난이도), 데이터 필드는 [SPEC §3·§8](../SPEC.md)을 따른다.

> **공개 범위:** 이 저장소를 공개하면 사건 문서의 정답도 공개된다. 저장소에는 샘플 사건만 두고, 출시용 사건의 문서·시드·평가 데이터는 비공개 위치에서 주입한다.

## 1. 소재 규칙
- 모든 사건은 **완전 창작**이다. 알리바이, 밀실, 시간 착오, 사고 위장, 바꿔치기 같은 추리 장르의 일반 장치만 빌린다.
- 금지: **실존 살인·범죄 사건의 각색**, 실명, 실제 상호·장소, 특정 가능한 세부 사항, 기존 추리 소설·드라마·퀴즈·게임 사건의 각색.
- 범행 방법은 **원리 수준까지만** 쓴다. 따라 할 수 있는 구체적 절차(약물 용량, 장치 개조 방법 등)는 쓰지 않는다.
- 범인·피해자·용의자는 모두 성인이다. 아동·청소년을 범인이나 피해자로 쓰지 않는다.

## 2. 개연성 점검표
모든 사건은 문서를 작성하기 전과 완성한 뒤 아래 7개 항목을 통과해야 한다. 사건 문서에는 항목별 점검 결과를 표로 남긴다. 하나라도 "편의적 우연"으로만 설명되면 보완하거나 보류한다.

| # | 항목 | 통과 기준 |
|---|---|---|
| 1 | 동기 | 살인을 감수할 만큼 크고 구체적이다(금액, 처벌, 잃을 것). **"왜 하필 지금"인지 촉발 사건이 있다** |
| 2 | 방법 | 범인에게 필요한 지식·접근 권한·기회가 있다. 결과가 확실하다(운에 기대지 않음). 현대의 상식(휴대폰, CCTV, 누전차단기, 부검, 카드 기록)에 걸리지 않는다. 걸린다면 그 이유가 사건 안에 설정돼 있다 |
| 3 | 범인 행동 | 범인이 바보 같은 실수를 하지 않는다. 단서는 범인의 부주의가 아니라 **피할 수 없는 흔적**에서 나온다 |
| 4 | 무고한 용의자 | 각자 의심받을 이유(동기 또는 기회)가 있고, 각자 배제 근거가 단서·사실로 존재한다 |
| 5 | 해결 가능성 | 공개 정보 + 단서 + 질문만으로 논리적으로 도달할 수 있다. 다른 해석은 단서가 배제한다. 정답 요소마다 최소 2개의 독립적인 근거가 있다 |
| 6 | 타임라인 | 분 단위 실제 타임라인에 모순이 없다. 모든 인물의 위치가 시간대별로 정의돼 있다 |
| 7 | 수사 현실성 | 경찰이 즉시 풀었을 사건이 아니다. 플레이어가 수사 파일을 받아 푸는 이유가 있다(사고로 종결될 뻔함, 고립돼 경찰 도착 전 등) |

- 점검은 평가 세트와 별개다. 평가 세트는 LLM 판정 품질을, 점검표는 이야기 품질을 본다.
- 플레이테스트 설문의 "판정이 납득됐는지"와 별도로 "**진상이 납득됐는지**" 문항을 추가한다(SPEC §17).

## 3. 표현·글쓰기 가이드
- 톤: 귀여운 픽셀아트, 진지한 사건. 공포 연출 없음.
- 사망 서술은 **검시 소견 수준**의 건조한 문장만 쓴다("사인은 급성 알레르기 반응으로 추정된다"). 시신·상처 외형, 고통, 범행 장면 재현은 쓰지 않는다. 피해자를 희화화하지 않는다.
- 맵에는 피해자를 그리지 않고 현장 표시선과 증거 번호표만 둔다.
- 사건 자료는 수사 기록체(건조한 평서문, 날짜·시각·장소 명시). 시스템 문구는 해요체.
- 길이: 사건 개요서 400~800자, 관련자 소개 1인당 60자 이하, 오브젝트 설명 80자 이하, 일반 단서 120자 이하, 진술서 120~250자, 해설 600~1,500자.
- 단서는 진상을 직접 말하지 않고 **관찰 사실만** 적는다. 진술서의 거짓 진술은 사실 시트에 반드시 "OO의 진술 중 ~는 사실이 아니다"로 기록한다.

## 4. 사건 문서 형식 (`<slug>.md`)
```markdown
# <사건 제목>
- slug / 난이도 / 질문 한도 / 맵 key / 상태

## 1. 사건 개요서                 (플레이어 공개, 수사 파일 첫 장)
- 사건번호 / 발생(발견) 일시 / 장소 / 피해자(이름, 나이, 직업)
- 검시 소견 요약(사인, 추정 사망 시각 범위)
- 현장 상황(발견 경위, 출입 상태, 특이 사항)

## 2. 관련자                       (플레이어 공개)
| id | 이름 | 나이 | 피해자와의 관계 | 공개 정보(60자) |

## 3. 공개 타임라인                (플레이어 공개, 확인된 사실만)

## 4. 진상                         (내부 전용)
- 범인 / 방법 / 동기 / 트릭·반전(어려움)
- 실제 타임라인(분 단위)

## 5. 사실 시트                    (LLM 판정 입력)
| id | 사실 |
- 부정 사실을 명시한다("OO는 범인이 아니다", "외부인 침입은 없었다").
- 용의자마다 알리바이의 진위, 동기 유무를 적는다.
- 정의되지 않은 세부 사항은 IRRELEVANT로 판정된다.

## 6. 정답 요소 · 범인 지목 방어    (최종 추리 판정, SPEC §8)

## 9. 맵 스케치                    (ASCII, 구역·벽·오브젝트·현장 표시·스폰)
```

## 5. 평가 데이터 형식 (`<slug>.eval.json`)
```json
{
  "questions": [
    { "q": "피해자는 밤 10시 이후에 사망했나요?", "expected": "YES", "category": "direct" },
    { "q": "노경태가 범인인가요?", "expected": "CLARIFY", "expectedReason": "ANSWER_GUESS", "category": "accusation" },
    { "q": "노경태는 밤 10시에 가게에 있었나요?", "expected": "NO", "category": "circumstantial" }
  ],
  "answers": [
    { "answer": "노경태가 헤이즐넛 크림 원료에 땅콩 페이스트를 넣고 비상 주사를 치웠다", "expected": "SOLVED", "category": "correct" },
    { "answer": "노경태 땅콩 크림 주사", "expected": "NOT_SOLVED", "category": "keyword_stuffing" }
  ]
}
```
- 질문 category: `direct` 직접, `synonym` 동의어(같은 의미 쌍은 `pairId`), `negation` 부정문, `compound` 복합, `open` 열린, `asks_answer` 정답 요구, `answer_guess` 진상 전체 추측, `accusation` 범인 직접 지목(**모든 용의자**에 대해 작성), `circumstantial` 용의자 정황 질문(지목 방어 오탐 측정), `injection` 인젝션, `undefined_fact` 미정의 사실.
- 답안 category: `correct` 정답, `correct_synonym` 동의어 정답, `wrong_culprit` 범인 오답, `wrong_method` 방법 오답, `partial` 부분, `multi_name` 여러 용의자 이름이 나오는 답안, `keyword_stuffing` 키워드 나열.
- 최소 개수: 쉬움·보통 질문 30 / 답안 20, 어려움 질문 40 / 답안 25. 카테고리마다 최소 2개.

## 6. 맵 제작 규칙 (Tiled)
- 타일 16×16. 레이어: `ground`, `walls`(타일 속성 `collides=true`), `decor`(현장 표시선 포함), `objects`(오브젝트 레이어, 커스텀 속성 `objectKey`), `spawn`(포인트 1개).
- 맵 파일은 `shared/maps/<map_key>.json`. 설명·단서 본문은 맵에 넣지 않는다.
- 오브젝트 칸은 이동할 수 없다. 벽 위치에 놓이는 오브젝트(문 등)는 그 칸에 `walls` 타일을 두지 않는다.
- 콘텐츠 테스트가 검사하는 항목: 맵과 시드의 objectKey 1:1 일치, 오브젝트가 `walls` 칸 위가 아님, 모든 오브젝트에 도달 가능한 인접 칸이 있음, 난이도별 수치 범위.
